Substitution notes for your kit

DHT11 instead of DHT22

Wire identically to DHT22 — VCC to 3.3V, DATA to GPIO4 with the pull‑up, GND to ground. Firmware only needs the Adafruit DHT library set to DHT11 instead of DHT22. Expect noisier readings and a 50°C ceiling; fine for an indoor/demo run.

5.6kΩ ×2 instead of 10kΩ

Two 5.6kΩ resistors in series give ≈11.2kΩ, close enough for the DHT pull‑up — it isn’t a precision value, just needs to be in the 4.7–12kΩ range.

1kΩ ×3 instead of 1kΩ+2kΩ

Use one 1kΩ from ECHO to the junction, and two 1kΩ in series (=2kΩ) from the junction to GND. Same 1:2 ratio as the spec → 5V × (2kΩ/3kΩ) = 3.33V at GPIO33. Safe.

No tipping‑bucket rain gauge

Two options: (1) buy a cheap analog raindrop board (₹80–100) wired to GPIO15 as an ADC input, mapped to an approximate mm scale; or (2) for the demo, hardcode rainfallMm: 0 in firmware and narrate the flood scenario using the water‑level sensor instead — the advisory engine already treats waterLevelPct >= 75 as flood risk on its own.

Raspberry Pi not here yet

Run npm run dev:edge on your laptop and point the firmware’s EDGE_API_URL at your laptop’s LAN IP. When the Pi arrives, everything moves over by changing that one URL and running the same command there.
